# 01 · 判断设备状态（决定走哪条路）

> 装完工具后第一件事：搞清楚盒子现在处于什么状态。
> **状态决定方法，方法错了会白折腾。**

---

## 三种状态

```
① 能进系统          → 最省事，系统内 dd
② 只能进 LOADER     → upgrade_tool wl
③ 什么都进不去      → 短接 MASKROM
```

---

## 一、怎么判断

### 步骤 1：上电，看串口

接好串口（1500000 8N1），上电，看前 3 秒的输出。

| 串口输出 | 状态 |
|---|---|
| `U-Boot 2025.10 ...` + 模式表 + `Starting kernel ...` + 内核日志 | ① 能进系统 |
| `U-Boot ...` 但卡住 / 停在 `=>` / 报错 | ② 引导在，系统可能坏了 |
| `U-Boot SPL ...` 后停 | ② 引导半坏 |
| **完全无输出** | ③ 或串口没接好 |

> **没有串口怎么办**：插 HDMI 看有没有画面。有画面 → ①；黑屏 → 不确定（可能只是显示问题），
> 这时用步骤 2 判断更可靠。

### 步骤 2：试连接

**能登录系统**（串口/SSH/HDMI 都可）：

```bash
# 串口或 SSH 里执行
uname -a
```

有输出 → **状态 ①**，跳到 [03-只更新引导.md](03-只更新引导.md) 的方法 A。

**能识别设段**（用刷机工具）：

盒子断电，插 USB 到电脑：

```powershell
upgrade_tool ld
```

| 输出 | 状态 | 说明 |
|---|---|---|
| `... Loader` | ② | 引导在跑，但系统没起来 |
| `... Maskrom` | ③ | 只有 BootROM 活着 |
| `not found any devices` | 未知 | 需要短接试试（见步骤 3） |

### 步骤 3：短接试 MASKROM

如果 `upgrade_tool ld` 什么都看不到，按 [04-救砖-MASKROM.md](04-救砖-MASKROM.md) 短接：

- 短接后能识别为 `Maskrom` → **状态 ③**（能救）
- 短接后还是看不到 → USB 线/驱动/电脑问题，先排查这些

## 二、决策表

| 你的状态 | 想做什么 | 走哪份文档 |
|---|---|---|
| ① 能进系统 | 换引导 H↔G | [03-只更新引导.md](03-只更新引导.md) **方法 A** |
| ① 能进系统 | 重装系统 | [02-刷系统到eMMC.md](02-刷系统到eMMC.md) |
| ① 能进系统 | 加 U 盘双系统 | [05-双系统与切换.md](05-双系统与切换.md) |
| ② LOADER | 换引导 | [03-只更新引导.md](03-只更新引导.md) **方法 B** |
| ② LOADER | 重装系统 | [02-刷系统到eMMC.md](02-刷系统到eMMC.md)（从「加载 loader」开始） |
| ③ MASKROM | 任何操作 | [04-救砖-MASKROM.md](04-救砖-MASKROM.md) → 转 02 或 03 |

**简单记法**：

```
能进系统 → 系统里 dd，最省事
有 LOADER → 工具里 wl，需要电脑
只有 MASKROM → 短接兜底，永远有效
```

## 三、状态判定速查（串口日志特征）

### 状态 ① 正常启动

```
U-Boot 2025.10-dirty (...)
Model: Onething P3 RK3566 BOX
SoC:   RK3566
DRAM:  2 GiB
...
+-------+----------+---------+-------+
| MODE  | USB-boot | rockusb | UMS   |
+-------+----------+---------+-------+
| L10-H |   YES    |   no    |  no   |  <== active
+-------+----------+---------+-------+
...
1  extlinux  ready  mmc  1  ... /extlinux/extlinux.conf
** Booting bootflow ... with extlinux
1:      Armbian
Starting kernel ...
[    0.000000] Booting Linux on physical CPU ...
```

### 状态 ②-a 引导好但系统坏

```
U-Boot 2025.10-dirty (...)
...
Scanning bootdev 'mmc@fe310000.bootdev':
（没有任何 extlinux，或报 Cannot read filesystem）
```

→ 引导正常，分区/系统有问题。走 03 方法 B 刷引导，或 02 重装系统。

### 状态 ②-b 引导半坏

```
U-Boot SPL 2025.10-dirty (...)
（到此为止，没有 U-Boot proper）
```

→ idbloader 在，u-boot.itb 坏了。刷完整 `u-boot-rockchip.bin`（它内嵌 itb）。

### 状态 ③ 完全无输出

```
（串口什么都没有，等 10 秒也无输出）
```

→ IDB 无效或 eMMC 不响应。短接进 MASKROM。

**先排除串口本身**：串口 GND 有没有接？TXD/RXD 有没有交叉？波特率是不是 1500000？

---

## 四、一个容易混淆的点

**「有 U-Boot 输出」≠「系统能起来」**，也**≠「能刷机」**。

| 能力 | 依赖什么 |
|---|---|
| 有串口输出 | IDB + U-Boot proper 都正常 |
| 能刷机（upgrade_tool 识别） | 需要 **LOADER**（G 模式按 `r`）或 **MASKROM**（短接） |
| 能 U 盘启动 | 需要 **H 模式** + 有可引导的 U 盘 |
| 能进系统 | 引导 + 内核 + rootfs 都正常 |

所以可能的状态组合：

| 串口有输出 | 能刷机 | 能进系统 | 说明 |
|---|---|---|---|
| ✅ | ❌ | ✅ | 正常跑着，H 模式（最理想） |
| ✅ | ✅ | ✅ | 正常跑着，G 模式 |
| ✅ | ✅ | ❌ | 引导好的，系统坏了 |
| ✅ | ❌ | ❌ | H 模式 + 系统坏 → 只能短接 |
| ❌ | ✅ | ❌ | 引导坏，靠 BootROM |

> **最容易踩的坑**：H 模式 + 系统坏了 → 按 `r` 进不了 rockusb（H 模式没这能力）→ 以为板子死了。
> 实际只要短接进 MASKROM 就能救。

## 五、确认状态的完整命令清单

```bash
# 在能进系统的情况下（状态 ①）
uname -a                                          # 内核版本
cat /proc/cmdline                                 # 启动参数
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT                # 存储布局
sudo dd if=/dev/mmcblk0 bs=512 skip=64 count=18365 status=none | sha256sum
                                                  # 引导固件哈希（对照 files/SHA256SUMS.txt）
p3boot status                                     # 一次性启动标志
```

```powershell
# 在电脑侧（状态 ②③）
upgrade_tool ld                                   # 看是 Loader 还是 Maskrom
```

把这两组输出记下来，任何问题都能快速定位。
