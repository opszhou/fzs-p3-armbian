# 06 · 故障排查

> 按「现象」查表格。每条都给原因和具体解法。

## 一、连不上设备

### `upgrade_tool ld` 显示 `not found any devices`

| 排查顺序 | 检查项 | 怎么做 |
|---|---|---|
| 1 | **USB 线** | 换成确认能传数据的线（很多线只能充电） |
| 2 | **USB 口** | 用主板后置 USB2.0，别用前面板、别用 hub |
| 3 | **驱动** | 设备管理器是否有黄色感叹号 → 重装 DriverAssitant 并重启 |
| 4 | **短接时序** | 断电→短接→插 USB→上电→等 1~2 秒→松开 |
| 5 | **换电脑** | 排除电脑问题 |

### 显示 `Loader` 而不是 `Maskrom`

不是故障，但**某些写操作会被厂商 uboot 拒绝**。

```powershell
upgrade_tool db files\MiniLoaderAll_p3_l1.bin
```

先加载 loader 再写。如果 `db` 也失败 → 重新短接，确保进的是 `Maskrom`。

## 二、写入报错

### `Open loader failed(err=-1)`

**原因**：文件路径不对。

```powershell
# 常见错误：路径写错
upgrade_tool db E:\tvbox\rockchip\phase3b\MiniLoaderAll_p3_l1.bin
#                              ^ 多了一个 3，应该是 phaseb

# 正确：用相对路径，确保当前目录有 files\
cd handmade
upgrade_tool db files\MiniLoaderAll_p3_l1.bin
```

**验证**：

```powershell
Test-Path files\MiniLoaderAll_p3_l1.bin    # 应为 True
```

### `Error: Execute: Switch storage to EMMC failed`

**原因**：设备跑的是厂商 uboot 的 usbplug，不支持切换存储命令。

**解法（按顺序试）**：

1. 短接进真正的 MASKROM（`ld` 确认显示 `Maskrom`），先 `db` 再 `wl`
2. 换 `upgrade_tool` 版本（v2.46 较稳）
3. 如果 `wl` 直接报这个错 → `db` 没生效，重来

> 这个错误我们在**第一次**刷机时遇到过，原因是设备处于 LOADER 而不是 MASKROM。

### `Error: Usb error: bulk write: 送到系统上的设备没有发挥作用`

**原因**：USB 传输层失败（不是协议问题）。

| 解法 | 说明 |
|---|---|
| 换 USB 口 | 优先后置 USB2.0 |
| 换 USB 线 | 劣质线常见 |
| 缩短线长 | 超过 1 米容易出问题 |
| 别用 hub | 直连电脑 |

### `创建IMAGE对象失败, 停止执行!`（RKDevTool 图形版）

**原因**：RKDevTool 是 **32 位程序**，地址空间上限 2GB，装不下 2GB+ 的镜像。

**解法**：改用命令行 `upgrade_tool`（64 位），或者把镜像切成 ≤256MB 的分片。

```powershell
# upgrade_tool 没这个问题，直接写整包
upgrade_tool wl 0xC8000 03_rootfs.img
```

### `Download Boot Fail`

USB 通信不稳。换线、换口、重新短接。

## 三、刷完起不来

### 串口完全无输出

| 可能 | 验证 | 解决 |
|---|---|---|
| 引导写错偏移 | 应该写 `0x40` 不是 `0x0` | 重新短接，确认 `wl 0x40` |
| 文件损坏 | 比对 `SHA256SUMS.txt` | 重新下载 |
| 引导区长度不够 | 应该是 18,365 扇区 | 用 `files/` 里的固件 |
| eMMC 芯片异常 | `upgrade_tool ld` 还能识别 | 芯片没死，重刷 |

### 串口有 SPL 输出但卡住

```
U-Boot SPL ...
（然后没有下文）
```

| 可能 | 解决 |
|---|---|
| u-boot.itb 损坏 | 重刷完整 `u-boot-rockchip.bin`（它内嵌 itb） |
| 只写了 itb 没写 idbloader | 写整包，不要只写 itb |

### 串口正常但系统起不来

看内核停在哪个阶段：

| 日志 | 含义 | 解决 |
|---|---|---|
| `extlinux ready` 后停 | 内核/initrd 读失败 | 系统镜像没写全，重刷 `02_boot.img` |
| `Unable to mount root` | rootfs 挂不上 | 重刷 `03_rootfs.img` |
| `Kernel panic` | 内核崩溃 | 检查 dtb 是否匹配 |
| 卡在 `Starting kernel ...` | 内核起来了但无输出 | 加 `video=` 参数或检查 HDMI |

## 四、模式相关

### 插着 U 盘却从 eMMC 启动

**原因**：当前是 **G 模式**（USB 当设备，读不了 U 盘）。

**验证**：串口启动日志看模式表：

```
+-------+----------+---------+-------+
| MODE  | USB-boot | rockusb | UMS   |
+-------+----------+---------+-------+
| L10-H |   YES    |   no    |  no   |
| L10-G |    no    |   YES   |  YES  |  <== active    ← 这行有 active = G 模式
+-------+----------+---------+-------+
```

**解决**：刷 H 固件（见 [03-只更新引导.md](03-只更新引导.md)）。

### G 模式按 `r` 不进 rockusb，反而打印 "U-Boot console"

**原因**：**旧版固件 bug**（r 键的返回值被误改成 0，导致 G 模式也走命令行分支）。

**解决**：换 `files/` 里的新固件（`293ce97d…` 之后版本）。

**验证修好了**：

```
MODE:  L10-G ...
Recovery: press 'r' within 3s for U-Boot console...
（按 r 后）
Entering rockusb loader (Ctrl+C to exit)...      ← 应该是这行
```

### 菜单序号重复（`1. 1. Armbian`）

**原因**：旧版固件把序号写进了菜单标题，而 bootmenu 自己也会加序号。

**解决**：换 `files/` 里的新固件。新菜单：

```
1. Armbian (eMMC)
2. USB boot
...
```

### UMS 选了但电脑看不到磁盘

**这不是故障**——UMS 是给**电脑**看的，不是给盒子系统看的。

| 现象 | 说明 |
|---|---|
| 选 UMS 后盒子卡住、SSH 不通 | ✅ 正常，U-Boot 在等电脑连接 |
| 电脑出现 1.99G 磁盘 | ✅ 正常，那是 eMMC 的 p1 分区（Windows 只认第一个分区） |
| 盒子系统里看不到盘 | ✅ 正常，它压根没启动系统 |
| 想退出 | 串口按 `Ctrl+C` |

## 五、系统运行问题

### 卡顿、IO 冻结十几秒

**原因**：U 盘写只有 7.1 MB/s，默认 `dirty_ratio=20%` 会攒 392MB 脏页再回写，需要 55 秒。

**解决**：见 [05-双系统与切换.md](05-双系统与切换.md) 的「性能调优」节。

### 首次启动卡很久

**正常**，要扩容分区 + 生成密钥 + 初始化服务，**2~3 分钟**。

判断是否正常：串口有没有持续输出日志。有输出 = 在干活，别断电。

### HDMI 黑屏但系统在跑

| 原因 | 解决 |
|---|---|
| 内核没配 HDMI 时序 | 加 `video=HDMI-A-1:1920x1080@60e` 到内核参数 |
| EDID 读不到 | 同上（强制模式） |
| 显示器协商问题 | 换线/换显示器试 |

改内核参数：

```bash
sudo nano /boot/extlinux/extlinux.conf
# 在 APPEND 行末尾加：video=HDMI-A-1:1920x1080@60e
sudo reboot
```

## 六、快速诊断命令

出问题时先跑这些，把输出发给懂的人：

```bash
# 1) 系统信息
uname -a
cat /etc/os-release | head -3

# 2) 存储布局
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT

# 3) 启动参数
cat /proc/cmdline

# 4) 引导固件哈希（对照 SHA256SUMS.txt）
sudo dd if=/dev/mmcblk0 bs=512 skip=64 count=18365 status=none | sha256sum

# 5) p3boot 标志状态
p3boot status

# 6) 内核日志里的错误
dmesg | grep -iE 'error|fail|panic' | head -20
```
