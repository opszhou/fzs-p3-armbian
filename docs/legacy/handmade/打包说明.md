# 生成离线包（把整套东西打成 zip）

> 用途：把这本手册 + 所有固件 + 系统镜像打成**一个 zip**，拷给别人就能独立刷机，不需要联网。

## 前提

本机需要有以下文件（大镜像不在 git 里，得自己放）：

```
本脚本所在目录（handmade/）
├── README.md
├── 00~07*.md
├── files/
│   ├── u-boot-L10-H.bin          ✅ 已在
│   ├── u-boot-L10-G.bin          ✅ 已在
│   ├── MiniLoaderAll_p3_l1.bin   ✅ 已在
│   ├── 01_gpt_bootarea.img       ✅ 已在
│   ├── 04_backup_gpt.img         ✅ 已在
│   ├── p3boot                    ✅ 已在
│   ├── 02_boot.img               ⬅ 需要你放进来（384 MB）
│   ├── 03_rootfs.img             ⬅ 需要你放进来（2.93 GB）
│   └── p3_armbian_slim.img       ⬅ 需要你放进来（3.32 GB，做 U 盘系统才需要）
└── tools/
```

## 用法

### Windows（PowerShell）

```powershell
cd handmade
.\make-bundle.ps1
```

### 输出

```
handmade\dist\p3-flash-kit-<日期>.zip
```

约 **3.5~3.9 GB**（取决于是否包含 slim 镜像）。

---

## 只打小包（不含系统镜像，约 30 MB）

适合"对方已有系统镜像、只要引导和手册"的场景：

```powershell
.\make-bundle.ps1 -Small
```

## 给对方之后的检查

对方拿到 zip 后：

1. 解压到 `C:\p3flash\handmade\`
2. 校验固件完整性：

```powershell
cd C:\p3flash\handmade\files
Get-FileHash * -Algorithm SHA256 | Format-List
```

与 `SHA256SUMS.txt` 比对，全部一致才动手。

## 为什么大镜像不进 git

| 原因 | 说明 |
|---|---|
| 仓库体积 | 3 个镜像 3.9 GB，git 会让仓库膨胀到无法 clone |
| 更新成本 | 每次改文档都要重传 4 GB |
| 已有渠道 | Release 和离线包都能传，没必要进版本库 |

小文件（固件 18 MB + 分区表 9 MB + loader 471 KB）加起来 28 MB，进 git 没问题，且它们**改动最频繁**（bug 修复、功能增强），放版本库里方便追溯。

## 打包脚本的两个已知坑（都踩过）

### 坑 1：`Compress-Archive` 处理不了 GB 级数据

PowerShell 5.1 的 `Compress-Archive` 会把内容缓冲进内存，3.9 GB 直接失败或卡死。

**解法**：用 .NET 的 `[System.IO.Compression.ZipFile]::CreateFromDirectory()`，它是流式写盘。

### 坑 2：`tar.exe -a` 打包中文文件名变乱码

`bsdtar`（Windows 自带的 `tar.exe`）创建 zip 时按**本地代码页（GBK）**写条目名，
Windows 解压时按 UTF-16 解释 → 中文名全是乱码（`00-飬.md` 这种）。

**解法**：同样用 .NET `ZipFile`，它固定按 **UTF-8** 写条目名并置 UTF-8 标志位。

**验证方法**：

```bash
python -c "
import zipfile
z=zipfile.ZipFile('dist/p3-flash-kit-YYYYMMDD.zip')
for n in z.namelist()[:5]:
    print(bool(z.getinfo(n).flag_bits & 0x800), n)
"
```

每行开头应为 `True`（UTF-8 标志位已置），中文显示正常。

> 如果对方用很老的解压工具（WinRAR 5.0 以前、老版 7-Zip），仍可能显示乱码 —— 用 **7-Zip 最新版** 或 Windows 10 1803 以后的资源管理器解压即可。
